修复前，浏览器只比较包编号和决策序号，同编号但不同点云的参考可以先显示，Python 随后才拒绝。这会污染人工参考核对，不能靠事后导入拒绝补救。

## 参考字段修订

盲看包 schema 不变。尚未实际使用的 `gse_structure_reference_v1` 新增必需字段 `blind_bundle_file_sha256`，值来自**实际导出的盲看文件字节**，不能重新序列化对象后猜测相同字节。

- 浏览器显示参考前：检查新增字节哈希等于实际加载文件哈希，严格检查参考字段、21 个决策及每项标注。
- Python 导入：同时检查字节哈希与既有 `blind_bundle_sha256` 对象规范化哈希。
- `BlindReviewSession.reveal_reference` 只有解析后的对象，只能检查新增哈希格式和旧对象哈希；不能宣称它独立核对了文件字节。

不在 JavaScript 中伪造 Python 的规范化 JSON：`1` 和 `1.0` 在浏览器里变成相同 Number，但 Python 对象哈希及文件字节可能不同。新增回归覆盖整数、小数、负零、科学计数和长小数。

## 文件大小与所有权

两端 `MAX_REVIEW_FILE_BYTES` 均为每个文件 128 MiB。Python 对 blind/reference bytes 的限制在哈希、解码、深复制之前检查，超限立即失败。此限制不是总内存上界，也不负责调用方已经解码的 `browser_record` 对象的文件读取。

已提交盲标与输入输出对象分离；参考说明只能在完整盲看和参考核对之后提交。导入仍明确返回 `automatic_training_eligibility=false`，哈希不证明身份认证或真人完成判断。

浏览器原始文件读取现使用 `parseStrictJSON`：先由 `JSON.parse` 验证语法，再逐对象检查解码后的字段名是否重复，全部通过后才返回对象。嵌套对象和 Unicode 转义同名字段均拒绝；数组中不同对象可使用相同字段名。保留读取文件前的 128 MiB 限制。此补丁发生在真实参考包和标签产生之前，没有改写任何真实标注。
