这周看了什么：Cano 的地下拓扑导航方法

Cano, Tardioli, Mosteo (2026)：Autonomous Navigation in Large-Scale Underground Environments Based on a Purely Topological Understanding of Tunnel Networks。

这篇工作先程序化生成地下隧道网络。它不是先随机堆一个三角网格，而是先生成 tunnel network 的连接关系；每条隧道由中心线 spline 控制形状，随后长成 surface mesh。因此完整网络天然知道哪里是交叉口、哪里有出口、不同 tunnel 是否连通，可以直接作为监督标签来源。

在感知端，他们将 VLP-16 的一圈 LiDAR 组织成 16×720 的 depth/range image：16 行对应垂直线束，720 列对应一周的方位角。轻量 2D CNN 从这张 range image 输出 360° 各方向的出口响应；再用 tracking 和 hysteresis 把逐帧的出口响应稳定下来，形成纯拓扑导航所用的事件。

他们用 50 个程序化地下环境、每个 10,000 样本，共 50 万样本训练。对我们的直接启发是：程序化 topology 可以提供可审计的出口和连接真值，range image 是一个很合适的快速 baseline；但“LiDAR + CNN 找出口 + 拓扑导航”本身已经被做过。我们后面要重点解决的是部分观测下的结构不确定性、稳定的 exit-stub 图，以及把它真正接入 M-TARE 的全局探索层。

论文链接：Cano et al., Journal of Field Robotics。另外也看了 TARE 的分层探索、地下 graph-based exploration、junction recognition，以及 PointContrast / LiDAR traversability 的自监督思路。

我们这周跑了什么

程序化地下拓扑真值 → CPU Raycast LiDAR → 当前帧规则出口检测 → 因果 Online Topometric Graph

先在一个已检查的 Cano 开发 world 上跑通完整接口：沿原始 graph 双边遍历，得到 240 帧 LiDAR；每帧 16×720，合计 276.48 万条射线。完整 graph/spline 没有给规则输入，只用于生成客观出口标签和最终评估。这样可以先看清“仅由当前 LiDAR 估计出口”会把多大的误差带入在线图。

同时，单图的 24 个固定 pose CPU LiDAR 合同通过：scan、标签和 reference 一致。五拓扑跨环境合同首次执行时，导入 provenance 检查发现 Python 指向了 site-packages 而不是锁定的 Cano 源码，因此在生成数据之前就停止；修复后的身份检查已通过测试，后续将按原规格重跑，不改变 world、阈值或方法。

当前跑出的结果

出口规则检测达到 F1 = 0.750（Precision 0.748、Recall 0.753），匹配出口的平均方位误差为 6.99°。这说明 range image 已能找出多数分支，但漏检和误检仍明显，正是后续 CNN 要改进的地方。

由规则输出驱动的在线图得到 43 个节点、50 条边、14 个未探索出口 stub；与同轨迹 oracle 图比较，节点 F1 为 0.828，几何边 F1 为 0.940。也就是说，图的增量表达和时序更新是可运行的，主要误差来自局部出口感知。
