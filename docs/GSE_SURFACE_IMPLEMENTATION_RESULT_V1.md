## 2. 方法的软件已经接到哪里

已实现确定性面片提取、A/B/C三组模型、独立三维锚点与开口输出、仅对已知标签计损失、实际模型调用到分段图的来源绑定。B和C参数量相同，三组当前各1228438参数；模型保留原始坐标与观测通路，几何没有被硬筛选成唯一输入。

模型使用的自由/障碍/未知证据已有射线穿格实现：首返回前才积累自由证据，无返回不擅自清空，窗口外返回不制造裁剪表面，分层表面不压成一层。面片间格子的分率只是观测特征，不是机器人可通过概率。

独立检查发现并在真实实验前修复两项图问题：稀疏位姿跳过中间节点时，旧逻辑会误连首尾；现在保存待确认轨迹，不插值伪造到达。模型判断和实际执行记录也已分开：记录穿越需要额外执行来源凭据，不能把模型的可通行字符串当作安全许可。实际控制器来源认证及跨访问配准集成尚未完成。

5090 D上的一次合成满尺寸检查使用57600点、4096面片、每片8邻居，完成C分支前向和反向，梯度有限。CUDA峰值分配607260160字节、保留708837376字节，主机峰值1726726144字节；前反向0.394711秒。没有真实扫描、旧权重或优化器更新。这只能证明单步可运行，不能用来保证全批训练时长或方法有效。

## 3. 实际问题与已执行备案

部署URDF只有外观和惯性，没有碰撞体。现有局部规划器参数不能完整定义车身净高、最大台阶、稳定坡度与接触约束。仿真中的0.75米是传感器/原点高度，30度是地面拟合排除条件，不能借来充当机器人能力。

因此执行用户已登记的第一项备案：停止物理根可达标签，继续真实观测、面片、可见开口和锚点软件。没有宣称已经学会地面可通行，也没有认定模型训练失败。源文件、SHA和逐参数依据见[机器人合同核对](GSE_SURFACE_ROBOT_TEACHER_STATUS_V1.md)。实际碰撞包络未补齐前，不能把这部分未知填成训练正负例。

## 4. 紧接着做什么

依据已封存选择清单，绑定新扫描/相对运动字段的精确输入卡，接入真实五帧材料并输出点云、面片与未知证据图。物理标签分支保持停止；可见锚点/开口仍需可信标签人口及代表例复核。有效标签与小样本拟合通过后，才做固定预算A/B/C训练和同后端图比较。
