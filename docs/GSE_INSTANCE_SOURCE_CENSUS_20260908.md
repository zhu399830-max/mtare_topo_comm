## 实际保存了什么

NPZ保存距离、有效掩码、因果相对运动以及教师专用的传感器位姿和`primitive_membership_code`。JSON保存码表、构造、基元端点、组合关系和旧诊断记录。来源码表允许一条回波关联多个基元，没有强行唯一化。

渲染器将CSG首次有效退出的完整基元来源集合编码保存。该编码不是逐三角形/侧壁/端盖编号，也不是点—路口支持答案。训练输入仍限定距离、有效掩码和相对运动，教师来源不得直接入模。

## 已确认的语义缺口

`terminal__circle__view2`只有一个基元`main`，码表所有有效回波均指向它；构造却有L=(-30,0,0)、R=(6,0,0)两个端点。侧壁与端部共享基元码，仅用“这个点属于main”不能确定它支持哪个端点。不能把两个端点都作为所有回波的确定正例，也不能自动取最近中心。

交汇中的基元来源、结构的incident关系可以作为待检查的证据链，但incident不等于当前表面已经充分支持该结构，尤其不能推广到遮挡或近邻路口。本次没有读取45观察之外的复杂合成条件来补标签。

## 可直接复用的更具体证据

现有`evaluation/gse_synthetic_straight_oracle.py::visible_straight_cap_rays`已经返回逐端盖、逐历史帧的射线索引，而不只是布尔可见性。它适用于登记的直线凸管道，使用实际64边形截面和10米窗口；不是通用矿井教师。

下一步先在固定`terminal__circle__view2`上核对这些已有索引所指的封存距离与端盖几何是否相符，区分端盖支持和同编号侧壁。该检查仅验证已有证据，不导出训练目标。若符合，再明确哪些其他类型仍缺支持定义；不能把尽头成立推广为交汇成立，更不能据此直接启动投票训练。
