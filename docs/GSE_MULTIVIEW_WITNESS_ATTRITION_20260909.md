# 为什么路口标签只出现在身后4米

这次只分析已封存的结果，不重新计算标签或训练模型。

## 两个问题已经分开

**1. 拟合部分：教师的分支证据随最早一帧丢失。**

对全部13个路口正例逐一查看五帧中的射线证据，再比较下一窗口：

- 13/13至少一条分支的全部证据只来自最早一帧。
- 前进1米后，最早帧退出窗口，同一真实路口仍在原始接口候选中（13/13）。
- 下一窗口全部将该路口标为未知（13/13），没有继续成为正例的情况。
- 这13个实例只有5个独立路口，几何变体不能扩充独立样本数。

具体例子：S02_3d_tree_small_C05的node_0035，在第一窗口，一条分支的3264条进入证据全来自最早帧，之后四帧均为0。其余两条分支在后续帧仍有证据；下一窗口则因不足三条方向而拒绝路口。

这解释了当前标签为何与五帧窗口的起始位置强绑定。它没有证明机器人走远后真的看不到路口，也没有证明随意降低“三条方向”要求就是正确修复。

**2. 校准部分：固定路线没有进入路口候选范围。**

5个校准父地图的180个观察，保存的nearby_junction_references全部为0，原始路口接口候选也全部为空。因此不能用它们校准路口检测或定位；不能把这个问题归咎于模型或证据阈值。

## 原教师条件是什么

核对的是旧运行source_snapshot.zip中的实际版本，而非当前同名文件：

- `gse_directed_interface_binding_v1`把射线和构造封口、进入方向绑定。
- `gse_reference_anchor_targets_v1`要求至少三个不同方向有进入或内部证据。
- `gse_interior_branch_evidence_v1`的内部替代证据还要求某一帧传感器同时严格位于至少三个源通道内部，并有唯一回波来源。

因此“看到了分支表面”和“满足这些封口/内部条件”不是同一件事。当前结果说明这个代理缺少多位置覆盖；是否漏掉实际可见结构，还须用固定合成反例和已保存观测验证。

## 后续处理边界

不再启动这批标签上的训练。下一低成本动作是用固定合成路口检查：原进入/内部条件是否会在分支表面仍可见时失效，并明确何种观测证据能够替代它。先验证代理本身，不直接换教师重做2259个标签。

校准人口单独保留“无候选路口”的覆盖缺口；不得凭模型分数重选样本，也不把无候选窗口自动标为完整负例。任何后续人口或教师修订都必须单独登记，旧结果保留。
