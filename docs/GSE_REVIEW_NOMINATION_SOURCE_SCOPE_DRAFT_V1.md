## 最小新增读取及身份映射

建议新增 **165 份构造 JSON（55 父 × 3 变体）及 P1b 的三个数组**，仅提取以下身份投影：

- 构造根：schema_version、parent_id、geometry_realization。
- base_construction：schema_version、endpoint_attachment_mode、node_degree_source；完整有序 primitives 中的 primitive_id、source_edge_id、source_tunnel_id、endpoints 的 primitive_id/endpoint_index/node_id。
- composition_operations：operation、node_id、degree、member_endpoints 的 primitive_id/endpoint_index/node_id。
- realized_primitives：仅完整有序 primitive_id，用于与 base 顺序核对。
- P1b：primitive_index [Q,32] int32、primitive_mask [Q,32] uint8、disconnected_overlap_packed [Q,32,4] uint8；Q 以每 task 的已封存完整序列人口核对。
- 仅必要 .zgroup/.zattrs、上述三个数组的 .zarray 和与精确行集合相交的 chunk；先过滤明确 task/字段路径，再核源 seal、解析和读取。

每个构造须保留全部 primitive 身份，不能只取 459 条当前行驶边：当前可见槽位可能引用其它支路。primitive_index 是构造有序 primitive 列表的下标，不是节点编号或 tunnel 编号。d0 使用 endpoint_index 0→1，d1 反向；source_tunnel_id 不用于折叠不同 edge。

**构造 JSON 包含几何坐标等未使用字段。读取整份文件字节并解析后只保留身份投影，仍然属于读取了含几何字段的文件；不能写“零几何字节读取”。** 应在新卡明确许可这些精确 JSON 文件并限制使用，而不是伪装成旧身份数组授权。原库存卡不授权新增关系标签/构造读取或提名。

### 是否还需 165 份 codebook？

本轮最小方案 **不新增 codebook 文件读取**，理由及依赖边界如下：

1. [P1b producer](../tools/v3/run_primitive_relation_p1b_teacher_materialization_v1.py) 的 _export_task 先读取 codebook 与构造，严格比较 codebook.primitive_ids 与 realized primitive 的完整顺序；[构造加载器](../src/mtare_topo/data/primitive_relation_materialization.py) 再严格核对 realized 与 base primitive 顺序。后续 relation 生成和 primitive_index 使用这个同一顺序。
2. 本轮读取的是已经物化的 primitive_index 和 overlap；不解码原始 primitive_membership_code，因此不消费 codebook.source_sets。重新读取 codebook 对这个接口不是必要输入。
3. **P1b 的 group.attrs 更新代码没有写入 primitive_ids**，只有 schema/parent/partition/variant/slot/history/traversal 等元数据。不能声称已封存 .zattrs 自带有序 primitive 字典；本轮也没有重新打开真实 .zattrs。映射应来自新允许的构造 ID 顺序及绑定的 P1b producer/source-seal 证据链。
4. 这不等于本轮重新验证了实际 codebook。下一卡须绑定原 P1b producer 来源版本、输入来源 seal 与完成证据，明确继承的是原 producer 的逐 task 等式检查。如果该来源链不能核实，停止；不能无证据继续，也不能悄悄多读 codebook。

### 为什么不是只读 55 份 base？

[P1a producer](../tools/v3/run_primitive_relation_p1a_sensor_provenance_export_v1.py) 对每个 world × realization task 分别调用同一 base 构造函数，再生成变体；没有发现跨变体 base 身份投影相等的实际断言。[无损复制 corrective](../tools/v3/run_primitive_relation_p1a_lossless_storage_corrective_v1.py) 只校验每 task 的原文件与复制文件哈希相等。算法预期共享结构不等于三份数据已逐项实证一致。

因此建议新读取 165 份，比较每父三变体的**有序 ID、edge/endpoint/incidence/degree 投影**完全一致；几何坐标和形状本来可以不同，不要求整份 JSON 相同。只读一份不能宣称完成三变体身份核验。

## overlap 的确切含义与解码

[原关系生成](../src/mtare_topo/data/primitive_relation_targets.py) 先取五帧有射线支持 primitive 的有序并集。对于其中不共享构造端点的不同 primitive，只要至少一帧的 azimuth 支持位图相交，就将 pair 标为 1。垂直通道已折叠为 720 个方位列；它不是跨时间随意并集、同一条射线、物理碰撞、隐藏连接或已经证明的人类感知混淆。

[存储代码](../src/mtare_topo/data/primitive_relation_storage.py) 沿第二个 slot 维使用 little-endian packbits。单观察 [32,4] 解码 axis=1/count=32；批量 [Q,32,4] 应沿最后轴解码成 [Q,32,32]，不能直接误用单观察轴号。pair 的 i/j 必须先查同一行 primitive_index，再查同 task 完整构造 ID 顺序。

alias 只能以该字段作为**候选提名依据**。如何让四类互斥、如何跨方向/窗口/变体按独立结构去重仍须事先冻结，不能把 overlap 自动当人工标签或无歧义真值。

## I/O 估计：有效行不等于实际 chunk 解码行

按原 producer 的 256 行 chunk 规则，165 tasks 三字段预计读取 2,880 个 chunk，解码 239,838 行，其中只保留 62,718 个有效行；177,120 行是 chunk 连带数据，不进入选样或统计。三个字段合计有效数值字节 18,062,784，连带解码数值字节 69,073,344。这不是磁盘压缩字节或峰值 RAM。

**这些 chunk 数是按源码和封存行号推导，不是新读取 .zarray 后的实测值。** 新卡若采用此布局预算，必须先核真实三个 .zarray 的 shape/dtype/chunks，再读 payload；不符则停止并报告，不偷偷扩 I/O。实际压缩字节、构造文件体积仍未知。

## 预登记后必须停止的条件

1. 任何输入 seal/JSON 身份/精确行集合 SHA 漂移，或路径进入 C08—C10、扫描、位姿、几何数组、模型/权重。
2. 三变体 base 身份投影不同、realized/base 顺序不一致、edge 与两个 endpoint 无唯一对应；degree 不等于 edge-incidence 端点人数、端点重复或缺失。不得用 tunnel 合并掩盖。
3. P1b shape/dtype/chunk 不符冻结合同；mask 非二值，活动 index 非整数/越界/重复/非原有序集合，非活动 index 不为 -1。
4. unpack 后非对称、对角非零、非活动槽位含关系，或同构造相连 pair 却被 disconnected 标正。
5. 三变体源序列/帧身份不能与封存行账本一致对应。跨变体可见 mask/overlap 本来允许不同，不强求标签相等。
6. 预先冻结四类规则后，独立结构人口不能满足配额：停止受影响选择并如实报告，不能改分区、短化 21 步、跨穿越拼接或用相邻窗口重复补数。
7. 只有序列索引连续不能证明物理执行连续；保持 continuity_requires_source_audit=true，duration_s=null。未读取的构造/可见片段/独立结构/人工标签人口一律未知。
