# 看见分支，不等于穿过构造封口

固定解析T形通道的软件反例已运行两次，均exit0。读取原封存源码归档中的两个证据函数，不使用当前同名算法冒充旧版本；没有读取真实地图或重新生成训练标签。

三个矩形通道分别向西、东、北延伸。传感器在东侧通道内的5个位置（x=1.2至1.6米），每位置向三条分支各发出一条射线。通过射线与盒子的解析区间求并集首退出点，验证15个目标均是无遮挡首返回、且表面来源唯一，不是仅凭构造ID声称可见。其余历史接口槽位全部无效，不冒充完整LiDAR扫描。

| 检查 | 西侧 | 东侧 | 北侧 |
|---|---:|---:|---:|
| 真实可见首返回 | 5 | 5 | 5 |
| 旧封口进入证据 | 5 | 0 | 0 |
| 旧内部替代证据 | 0 | 0 | 0 |

原因很具体：东侧分支中传感器本来就在里面，不需要穿过它的起始封口；北侧射线经几何重叠侧面进入，没有穿过正向起始封口。内部替代又要求传感器同时在至少三个源通道内部，本例不满足。

因此旧条件并不是一般的分支表面可见性判据。结合真实保存证据中13/13正例丢最早帧后转未知的现象，下一步应评估观察表面支持的教师备案，而不是继续用原教师扩大训练。

**边界：** 三条可见表面射线不足以证明完整路口结构可辨认，更不是地面可通行证明。本例未调用完整标签生成器，也未证明真实2259观察应当怎样改标签。不能据此改成“看见三种来源就标路口”；不同隐藏连接可以给出相同可见表面，必须先通过该反例。校准人口没有路口候选是另一个问题，不能靠修改证据函数解决。

下一步固定为评估已有表面支持/开口证据实现，在相同可见观测、不同隐藏连接以及遮挡反例上检查是否会伪造确定结构；只做合成检查和代码复用，不新建批量教师或训练。
