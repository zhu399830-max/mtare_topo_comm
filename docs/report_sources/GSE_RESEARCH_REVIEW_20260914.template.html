从地下几何观测到拓扑探索
我们做了什么，为什么还没有完成

一份基于现有代码、已保存实验与真实结果图的复盘。按研究问题串起方法演变，分清有效进展、失败结果和仍缺少的证据。

先说结论：我们已经积累了地下数据、训练模型、离线图和仿真运行；旧出口模型＋规则图也曾真实闭环运行。但当前“几何基元关系带来更好的结构维护与探索”这一核心主张尚未验证。最新工作已把真实扫描送入冻结模型，并完成历史候选检索和点云配准；学习结果还没有实际改变原生探索路线。

本报告不新增训练、标注或仿真，不修改旧失败。历史文档中“正在运行／下一步”的表述不代表今天状态。数字按各自数据与评价范围保留，不跨版本拼接排名。

01要做的不是“识别一个类别”，而是帮助探索

导师方向可以概括为：从激光看到的几何基元及其关系中提取结构信息，帮助机器人维护“去过哪里、还有哪些方向没走、哪些观察可能重复”，再辅助探索规划。几何基元不是最终答案，拓扑图也不只是把点连上线；它们必须改善实际任务维护。

激光与运动当前及过去五帧，不看未来
几何与学习特征表面位置、方向、范围、相互布局
结构对应与任务当前主要缺口：把局部对应变成可信任务关系
拓扑辅助决策新关系模型尚未改变真实路线
原规划器执行已有机器人运动记录，保留避障与控制
工作层已经做到还不能说
数据与自动监督程序化三维世界、激光、中心线、构造来源与多版标签已保存每个构造标签都等于机器人能看到的结构
模型出口、扫掠基元、中心检测、面片关系、逐射线关系都实际训练或评估过存在一个已通过完整验收的最新结构模型
拓扑旧出口＋规则图有离线回放和闭环记录；新任务后端及执行接口有实现旧图成绩就是新几何关系的收益
仿真旧方法完成过30例矩阵；最新原生基线跑600秒，接线补录跑120秒最新学习方法已完成整图探索或三组长对照
论文证据已有数据、基线、失败分析和结果图严格未见、多机器人收益和投稿论文已经完成

这里的“因果回放”只指按真实时间顺序，只用当时已经有的观测更新图，不是因果推断算法；“确认边”应有实际穿越依据，而不是两个向量相似就创建连接。

当前状态依据：当前计划、项目状态、最新系统接线记录。

02地下地图不是手绘示意图，训练输入也不是完整地图

先生成通道骨架，再生成三维洞壁

复用 Cano 相关程序化生成器，先确定树形、单环、多环等连接骨架；用三维平滑中心线描述每条隧道走向，再沿中心线铺设截面生成洞壁表面和三角网格。因而同一张地图同时具有两种信息：用于激光碰撞的真实表面，以及离线可查的构造记录。后者不是部署时可用的地图。

同一个拓扑，改变几何外形

后来的基元数据使用椭圆、过渡形状和圆角矩形三种截面实现。目的不是把隧道简单分成三类，而是让相同连接关系拥有不同外形，用于区分“记住外观”与“学习结构”。每个拓扑父地图的全部变体留在同一个数据分区。

03Teacher 就是“自动算训练答案的程序”，但答案需要符合观测

这里没有另一个神秘的大模型负责告诉网络所有答案。主要标签来自生成地图时保存的拓扑、中心线、截面参数和激光射线来源。后期也使用了AI辅助的可见区域复核，但它必须单列，不等于人工金标。

来源能算什么不能直接当成什么
生成拓扑与中心线哪里有分叉、隧道怎样连接、轴向和行程当前激光必然看到了全部分叉
截面和洞壁网格形状、宽高、射线命中表面完整可通行地面或机器人安全证明
射线来源与五帧历史哪些表面有观测、哪些内容仍未知不同生成编号必然是不同通道
部分AI方向参考可见核心区域的保守支持与复核说明所有回波的唯一支路身份、人工完整标注

为什么在标签上花了很多工作？

完整地图知道墙后有通道，但当前激光可能只看见墙。若把隐藏连接也作为确定答案，网络面对相同观测就会被要求给出相互矛盾的判断。另一个具体问题是：一面墙可能同时支持路口两条方向，不应该强制属于唯一支路。

早期变化事件标签还存在未来信息与重复计数风险：事件周围连续很多帧都被标成“发生变化”，其中有些在当时还不能确认。后来改为因果确认、保留未知，并按物理事件计数。某一版因果标签覆盖188,126观察，但独立几何变化只有76个；不能用十几万帧掩盖稀有事件不足。

“未知”不是“没有”。训练时未知项不产生负例损失；推理时也不能拿真实地图把未知预测预先删掉。否则表面上精度很高，但机器人部署时根本做不到。

依据：Teacher与历史训练报告、中心监督第18—20节、可观察方向参考记录。

04最早的出口模型确实有结果，但它不是现在要证明的创新

方法：激光距离图 → 出口方向 → 规则建图

将16层、720个水平方向的激光量测组织成距离图，用环形卷积处理360°边界；M1D模型预测方向、分支数及局部角色。图后端根据持续观测、距离和运动记录建立节点与边。这是一条Cano-like适配基线，不是“几何基元关系直接改善建图”已经成立。

这组旧C08回放用了3个开发世界、4,773个唯一激光帧，三个模型共14,319次推理。B0是单帧激光几何出口规则，不是原M‑TARE，也不是完整复现的Cano。参数在开发回放中选择，不能称严格测试。后续旧C09报告还明确记录其检查点选择污染，不能因方法改名就恢复“完全未见”资格。

中间也完成过轨迹几何修正

早期支撑几何曾把窗口外轨迹整体下移，数值检查通过却违反原位姿要求。修正版将LiDAR渲染网格与动态支撑用途分开，沿当前路线查询支撑，避免上下层隧道混用。历史报告记录4,773帧通过三档检查，4,307个窗口外位姿逐元素不变。这是回放几何有效性的证据，不是网络识别或探索性能的提升；旧失败保留。

不是“从未做过闭环”：旧出口＋规则图完成过30例

旧V5出口模型＋确定性图系统后来完成30/30例、10个配对区组、合计18,000仿真秒。它保留为旧基线和失败分析，不是新基元关系方法的完整闭环。旧V9曾出现回到旧节点却不更新当前位置、选错出口后反复重试的问题；V5补了返回锚点和执行反馈纠错。

30例完成指运行和记录完整，不代表每例探索完地图，更不等于优于原M‑TARE。早期17/30中期图不能当最终比较表。本报告不把不同阶段、不同模型的数据强行排在同一张性能榜上。

旧系统证明“出口感知＋规则图＋机器人执行”能够运行。它给我们留下了环境、传感器接口、图和执行经验，但没有验证现在主张的“几何关系的独立贡献”。

依据：早期阶段结果、开发回放独立复核、旧闭环方法与失败机制（中期）；30/30最终状态见机器状态字段 phase6_v5_combined_correction_stochastic_v1r2_status。

05为什么从出口，转向三维基元与组合关系？

只有出口角度，很难区分相似路口、上下分层、截面变化。因此尝试把通道显式表示为沿三维轴线扫掠的截面，学习轴线、宽高、形状、端口关系和跨帧对应。相比单个“这是路口”的分类输出，它更接近导师要求的几何结构，但任务之间能否同时学好是实际难点。

Chamfer是两组表面点的距离类误差，不是已完成地图的定位精度。这里列出9.84米，是为了同时给出相对改善和绝对误差；不挑“改善百分比”掩盖实际还很粗糙。不同基元版本的指标不能直接与后面的中心检测精确率比较。

这条阶段路线的共同问题：形状重建有信号，连接判别却没有可靠成立。把局部相似性升级成全局相连、或让一个共享模型同时承担太多不稳定目标，不能靠增加训练轮数保证解决。几何路线没有被整体否定，但这些实现不能登记为合格建图前端。

06中心检测：位置已经能拟合，候选评分最终没有过关

图上的叉究竟是什么？

“中心”是给路口在空间中规定的一个参考位置。网络先提出若干坐标，再判断哪些坐标像路口中心；目的是给图提供稳定节点，不是识别完整通道结构。叉只是一个候选坐标，不代表几何基元、通道可通性，也不是已经建立的图节点。这条路线后来停止，不是现在最新主线。

有限诊断固定16个观察、12个中心参考、每观察32候选，共512个候选。先检查解码范围，再隔离位置损失、存在性损失和匹配，避免一看到检测差就换网络。真实输入和查询保持不变，真值只进入训练损失与评价。

07面片关系：确实做过公平拟合，但开发收益不够

“分块”不是仅给点云换颜色，它给网络建立局部几何单位

将五帧点云按相对运动对齐，在10米局部域按0.5米体素组织表面点；局部PCA计算中心、法向、范围和粗糙程度，同时保留点数、跨帧支持及不可靠标记。每块连接8个近邻，网络读取相对位置、法向关系与高差。曲面可以由许多局部面片近似，不必把整条洞壁拟成一个平面。

颜色只是块编号的可视化；真正新增的信息是每块的形状及块间关系。近邻边是信息交换关系，不是机器人可走的连接。该体素划分也不严格旋转等变，不能把确定性等同于旋转不变。

组别使用的信息要回答的问题
A：观测相同冻结编码特征＋坐标不显式加入面片几何能做到什么
B：自身几何A＋每个面片自己的几何属性显式局部几何是否有用
C：关系B＋邻居消息和几何关系组合关系能否进一步改善

这一轮直接训练轴向相似度和参考中心高差，三组使用相同修正版监督、初始化规则和2000步预算。它们继承已有预训练编码器，A不能叫“完全没接触几何监督”。C对B还同时改变消息传播与关系输入，不是最终单属性消融。

# 后来的逐射线模型：每条射线读取附近8个面片

依据：条件几何拟合、修正和开发评价记录。本节数据与下一节12观察不是同一批，不能因为数量相同就混用。

08直接学支路关系：已标答案全对，为什么完整结果仍错？

先发现了输入已经丢掉支路区别

原方案把一个粗扇区先汇总成一个向量。但同一扇区可能包含两条支路，汇总之后再要求模型唯一分类，信息已经丢了。12观察中19个粗候选仅6个有唯一条件参考，13个未知；A/B/C虽分数不同，最终账本都创建6个任务，决策没有变化。改用简单连通分解后候选变44个，未知增至35个，仍有7个混合候选，反而增加碎片。

因此实现逐射线读出：每条有效激光保留方向、距离、三维回波和五帧特征，读取局部8个面片，预测两条观测应同组还是异组；共同后端再结合吸引与排斥关系分组。这不是预测全局连接。

一次500步拟合已经真实跑完

仅C组，三个训练父地图的12观察、135,699条射线。参考来自部分AI复核核心，不是全场支路金标。训练仅监督已知关系，未知仍保留到完整预测里。

核对对象结果为什么仍不足
已标同核心关系98,699对全部正确只覆盖保守核心，不是全部墙面
已标异核心关系4,202对全部正确未知区域仍可能把两个核心间接串起来
未监督关系1,712,750对；其中1,700,999对输出高置信不参与损失不会自动让网络说“不知道”
原完整分组0/12恢复大分量内部同时有同组与异组关系，原后端整块拒绝

不重训，改为局部处理冲突后，恢复到10/12

保留原预测、阈值和全部射线，只阻止发生冲突的合并，不再清空整个连通分量。已标核心恢复从0/12变成10/12，没有已标核心间错并；剩下2例核心仍被拆开，另有5个纯未标组，正确性未知。这是后端保留一致部分的实际改进，不是新增网络的优势。

两例剩余失败具有具体证据：先前高分关系把未标表面并入核心，之后排斥关系又阻止正确核心合并。一例核心被分成591＋132条射线，另一例分成302＋2条。当前证据能说明关系整体冲突，却不能从未知边中唯一指定“应该改哪一条标签”。

补齐查询后又发现：广泛“同组”不等于方向支持

之后用同一冻结模型计算完整锚点—射线查询：从8,350条有支持变为135,699条全部有支持，但其中135,625条被多个锚点支持，每例支持锚点数中位27—30个（共32）。32锚点不是32条真实支路，不能直接算错误数；但这说明旧同组分数不能改名为有选择性的方向归属。

本轮结案：部分关系可学，完整分组与方向含义仍不合格。最新非互斥方向支持接口允许共享和未知，但尚缺独立排斥证据与部署查询对应，没有据此启动新训练。没有补跑A/B正式扩训、分支图或探索来掩盖这次失败。

依据：全部支路训练、冲突证书与完整查询记录；500步实际结果。严格12/12未通过与10/12局部改善同时保留。

09仿真确实跑了，但最新模型尚未成为路线决策的一部分

先把原M‑TARE底座真实运行起来

最新开发基线使用tunnel场景、seed11、单机器人、原起点。运行600仿真秒，保存3,000帧同步扫描与位姿，行程1,145.888米、598个目标点。没有收到探索完成信号。该结果证明原系统能运行并记录数据，不是整个世界已经探索完。

接入学习特征时，先后修复了具体数据接口错误

旧600秒记录缺原始激光及原生候选信号，不能把注册点云重新拼成训练时原始输入。后续做120秒最小补录，保留原控制器。第一版120个模型窗口只有14个处理成功、106个被完整三维姿态检查拒绝；原因是公共适配层只传平面航向，没有把已有完整旋转接口传到底层。

还发现原生注册器会改写时间戳，模型的“每秒窗口”与规划器的五帧窗口不一致。不能用最近时间硬配，于是在同一个原始处理回调里增加来源记录。新补录得到115个原生五帧窗口、575条唯一原始帧，冻结模型115/115处理成功。

最新已执行环节实际结果正确解释
显式来源补录120秒；231.876米；617原始扫描；115模型窗口扫描与模型来源接通，模型结果为事后处理
历史候选检索114时刻有候选；总计560项提出相似观测，不是认对560次地点
固定CPU点云配准156局部拟合通过，404拒绝表面可对齐不等于方向任务身份确认
访问记录绑定115时刻对应38次区域访问区域访问不是38个学到的路口
实时服务及局部执行接口软件／模拟ROS测试通过最新常驻服务尚无真实在线路线影响成绩
学习导致的真实路线变化0不能宣布新学习闭环完成

当前真正卡在哪里：局部结构与全局任务不是同一个对象

原M‑TARE全局路线候选通常是远处探索区域，当前网络描述的是身边10米局部表面。检索和配准只提供历史观测候选；当前排序策略却要求它们已经对应到一个有方向、并且带完成证据的任务，才允许延后访问。实际运行还没有产生这一类方向任务与完成证据。

当前扫描特征已实际提取
历史表面对齐156项局部拟合通过
同一方向任务？完成了？没有合法生产证据，不能从ICP或到达直接推断
调整全局区域顺序前提不满足，所以保持原路线

这次不是模型又训练失败，而是任务定义与接口前提不相容。到过一个位置，不等于走完它的全部分支；到达近处运动点，也不等于完成远处区域。继续增加日志、重复115窗口或接上一个函数，不会自动生成缺失语义。

截至报告日期，当前策略扩展与新长仿真暂停。三组至3,600秒的最新完整比较尚未执行；没有多机器人新方法成绩。原数据、权重和失败全部保留。

依据：真实输入、配准、访问和当前策略问题；560项配准原始汇总；实际排序前提见structural_route_policy.py。

对推进方式也需要负责任地复盘

此前有一段时间连续围绕评分器修补，却没有先确认训练目标和最终检测要求是否一致；又曾把“特征送到回调”描述得接近闭环，而任务来源尚未具备。复杂的记录与测试提高了可追溯性，但测试数量不能替代核心科学问题的进展。

更有依据的工作方式已经在一些诊断中体现：固定同一批位置只查评分、固定同一模型只查监督、固定同一批预测只查分组后端。这些干预让我们知道改善来自哪里。下一步也应先明确模型输出怎样改变一个实际任务，而不是再换一个网络名称。

审计的用途：排除漏帧、输入错位、未知当背景、未来信息和错误评分，防止把程序错误当科学结果。它的边界：审计通过不等于方法有效；反复检查同一已解决问题，也不能替代前向推进。

合理的后续缺口，不是再“自动开始一轮训练”

  1. 明确任务接入：把访问排序与任务完成分开设计；先定义全局候选怎样绑定可观察局部上下文。不能只是删除完成条件，也不能从局部配准制造任务完成。本项是建议，尚未实施。
  2. 证明学习实际参与：在同一候选、同一后端下，只替换学习／非学习对应，记录哪些建议变化、是否真正执行。全回退只能说明安全兜底工作，不能说明方法起作用。
  3. 再作完整配对：统一场景、起点、机器人与预算，比较原M‑TARE、共同非学习任务图、学习任务图。保留超时和失败，不把未完成案例删掉。
  4. 最后才扩展论文：独立开发优势成立后，才谈未见地图和多机器人。若系统跑通而没有独立收益，应如实保留工程成果，不把它包装成关系创新成功。

这条路线并非毫无基础，但距离可投稿成果还缺两条完整证据链：几何关系确实改善结构维护；结构维护改善确实减少探索漏走与重复。当前不能给出可信录用概率，也不能承诺再训练一次就解决。

可直接用于向老师汇报的一段话：
我们先建立了程序化地下数据和自动监督，用出口感知与规则拓扑验证过基础链路；随后围绕三维基元和表面关系训练了多种模型。已经看到局部几何可学、小样本关系可拟合，但完整检测、关系一致性和开发迁移存在明确失败。最近把原始扫描、冻结特征、历史检索与配准接入了原生仿真数据链，剩余核心问题是把局部结构对应转成可被规划器使用的任务关系。当前有可复现资产和失败证据，但尚未证明新几何关系方法能改善完整探索。
