# 标签核验中断：分配器地址空间，而非模型失败

正式核验在第53个观察申请约1.18MiB数组时失败。已完成52个观察全部保留；worker峰值RSS为361013248字节，远低于4GiB物理内存预算。旧执行器另设了worker3GiB虚拟地址空间限制。没有失败瞬间的进程映射，不能声称已证明该次全部内存增长的来源。

已完成无真实数据的复现：同一旧CPU环境，Open3D盒子、57600条固定射线、连续6次场景构建。即便OMP_NUM_THREADS=1，实际仍有35个线程。默认分配器VmSize为3734916KiB，RSS约323296KiB；设置MALLOC_ARENA_MAX=2后，VmSize约1704520KiB，RSS约323004KiB。六次调用的六类原始返回数组SHA-256逐项相同。另有软件测试在原3GiB地址空间硬限制下执行修正版并比较输出。

这支持一次有限的执行器修正：只将分配器arena数限制为2，不改Open3D射线算法、不改线程数量、不抬高内存上限、不改原V6归档和标签语义。它不是几何或模型成功证据，也不保证整个真实人口必定完成。

新运行使用独立v1r规格，复用完全相同2259观察数据卡，旧失败run不覆盖。重新计算全部窗口一次，用前52个已存原始接口和目标做结果一致性检查；不是挑选容易样本继续。再次失败不自动启动第二次资源修正。原始证据、未知和零目标窗口全部保留。

工具：`tools/v3/open3d_allocator_probe_v1.py`；测试：`tests/v3/unit/test_open3d_allocator_probe_v1.py`；执行器修正：`tools/v3/multiview_historical_teacher_v1r.py`。
