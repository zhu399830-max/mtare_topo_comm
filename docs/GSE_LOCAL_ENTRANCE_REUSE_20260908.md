# 局部入口：已有代码能复用到哪一步

## 后续实现结果

`teacher/saved_branch_evidence.py`已完成类型化读取，复用原`bind_axes`处理真实轴线而非connector方向；12项软件测试通过（0.21秒）。核对封存12例SHA后，全部63次支路关联成功绑定。J0的middle为+x，J1的同一middle为-x，不按来源ID折叠。读取保留分类型见证，入口位置/宽高/可达性为None；未新生成teacher或训练。旋转测试覆盖90度传感器朝向，实际人口仍是原有朝向，不宣称新旋转人口验证。

本次只读源码及已封存12例结果，没有新teacher、训练或基线推理。纠正任务错位，不修改历史成绩。

| 实际代码 | 能复用 | 不能当作什么 |
|---|---|---|
| `semantics/range_exit_baseline.py` | 当前范围图的近水平长距离扇区，默认7米下限与62分位自适应门限 | 不是三维入口位置，也不是完整近处支路探测；短或遮挡支路仍可能不满足门限 |
| `semantics/nonlearning_geometry_observation.py` | 旧事件/出口基线与已有类型接口 | 无运动对齐，最多6个方向token；根据距离和角宽估计的宽度不能冒充真实入口尺寸 |

| `teacher/gse_junction_interface_diagnostic_v1.py`及内部/侧向见证 | 路口—支路关联与原始射线记录 | 构造身份只能做参考监督，不能进入学生候选筛选；端盖不是实际开口边界 |

## 已有结果中可复用的量

逐例核对 `teacher_provenance.anchors[].interface_ids` 与 `witness_ray_indices`：21次路口参考每次3个有非空见证的关联，共63次。三种截面的每个view依次为3、6、6、6次。只涉及J0、J1两个构造节点，不能称63个独立结构。

这些记录说明“支路关联的部分参考”已存在，并不依赖支路必须延伸到10米窗口边界。现有10米窗口开口仍保留作原任务诊断，不能重命名为局部入口。

注意：关联见证有cap、interior、lateral entry/departure不同来源；有见证不等于完整物理可通行认证。方向还需通过原构造轴线和界面一一绑定，不能直接以显示图角度或窗口开口方向代替。

## 推荐的最小下一步，不再造一个完整teacher

先做**既有证据的类型化读取**，不重新生成标签：保留参考路口位置、逐支路见证索引与来源种类、同一坐标系下由原轴线得到的参考方向。将局部入口位置、宽高和可通行性明确标为尚未获得，而不是用路口中心或裁剪端点填上。

软件检查应覆盖：相反方向的同一物理通道两端不折叠；多路口不按tunnel ID误合并；缺见证保留未知；学生输入仍只有观测与运动。该读取不改变既有监督合同，不自动赋予训练资格。

随后才能决定是否将“路口附近支路方向及归属”作为版本化的第一项可学习任务，并如何补足入口位置。若采用，必须明确它比完整三维开口任务少了什么，不能把备用任务冒充主方法完成。

## 目前禁止得出的结论

不能直接在仅两个路口、无完整背景/负例的人口上训练后声称泛化；不能拿这些部分参考与旧基线输出数量硬算完整F1；不能因为63条记录存在就说几何组合创新已经成立。正式主比较仍须相同观测、输出任务和图后端，以及独立背景与父地图人口。
