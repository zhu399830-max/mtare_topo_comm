# 观测驱动候选：当前可复用接线与明确缺口

这是代码核对，不是新候选实验。没有生成标签、模型推理或训练；23项已有轴对、轴面片及候选评分测试通过（0.25秒）。

## 已确认的输入隔离

`RobustPrimitiveRelationBaseline.predict`仅接收五帧range/valid及因果相对平移、yaw。`axis_pair_proposals`仅接收最多32条三点轴线及有效掩码。旧运行入口先产生候选，再调用真值评分。构造节点、教师中心、真实连接无需进入候选生成。

原860人口已经有原始六字段输入引用、冻结特征、几何超点分块和部分结构标签，可以继续复用，不需要重新渲染地下世界。

## 不能直接把它当成熟检测器的原因

1. 上游`_candidate_runs`把五帧出口合并成720列水平角度区间，单个区间没有独立高度层标识；三维轴坐标不等于三维候选分组完备。因此同方向上下层分离不能宣称已支持。
2. 空出口时，上游使用最强水平列建立确定性轴线；少点时扩大选点，轴跨度不足时补足最低跨度。这些是旧几何基线的明确fallback，不是可靠通行证据，不能隐去。
3. `axis_pair_proposals`保留所有轴对，最多496对；异面交线中点仍是未验证假设，必须保留分离距离和外推距离。输出不确认连通，也无尽头检测器。
4. 旧`endpoint_attachment`包含近机器人端点的规则关联，不能作为新方案的已知图边。只复用轴几何，不复用这套连接结论。
5. 当前学习评分入口最多32查询、底层覆盖查询最多64；不能将上百候选直接塞入并截断。已有`candidate_coverage`可接受变长候选，但部分标签时只报告覆盖和未匹配数量，不能将未匹配都当误检。
6. 现有860监督没有完整尽头和背景人口，只有部分被观测支持的路口/分支。因此下一检查只能声称部分路口候选诊断，不是完整结构检测验收。

## 下一项有界检查

使用原860观察（282fit、578calibration；5个拟合父地图、4个校准父地图），不增删样本或读取测试世界。在独立数据卡与运行规格中绑定原输入引用和标签哈希后，CPU一次计算：

- 原默认非学习轴拟合及全部轴对候选；不得改默认参数或将规则attachment当边。
- 现有几何超点中心候选，以及与轴对的并集；直接复用既有分块，不重做PCA/分块。
- 真值只进入独立评分；记录所有候选、未知/退化轴对、外推/分离证据、每观察候选数、1/2/4米覆盖和一对一匹配。候选数增多不能单独算表示优势。
- 与当前自由查询失败及固定模板诊断并列解释，但不混成同预算检测排名。此项不输出学习成绩、完整F1、图或可通行性结论。

只先确认可用候选是否存在、代价及失败在哪里。候选缺失时筛选器无法补救；大量候选覆盖也不足以授权训练。不得看到覆盖好就自动恢复扩训。后续学习接口必须另外固定可观察正负/未知监督、重复处理、容量和输入对照。
