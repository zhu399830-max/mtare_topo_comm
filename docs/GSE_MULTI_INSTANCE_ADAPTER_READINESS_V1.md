# 多实例结构预测接入图：最小适配规格 V1

2026-09-05。当前方法的接口补齐，不是新研究路线或正式图实验。

实施更新：真实GPU训练封存后，已新增`src/mtare_topo/topology/gse_region_candidates.py`及30项专用纯合成测试；不修改任何已有模型、训练或图源。主代理合并旧query及完整训练运行器测试，共77项通过。现在已有无决策单观察候选转换，尚无真实数据接线、实例跟踪或图提交。以下后端剩余问题仍未解决。

本文件及候选层只依据既有源码及接口文档和合成输入；未读取真实地图、扫描数组、标签数组或权重，未运行图。最初训练期间只新增文档，封存后才新增独立候选模块；不修改模型、训练预算、数据、损失、图阈值或历史代码。

## 1. 要解决的具体问题

模型正在学习“局部结构中心＋事件＋成员归属”。旧图入口只表达“机器人此时看到一个事件”。两者不能直接互换，否则模型学出的中心和多实例信息会在接图时丢失。

| 已有 API | 实际能力 | 接新模型时的缺口 |
|---|---|---|
| `gse_region_queries.RegionPrediction` | 每观察最多 64 个候选；每候选中心、三类事件 logits、presence logit、成员 logits、不确定性；另有数值支持 mask | 没有完成候选去重、跨时刻实例对应、置信度校准或端口宽高预测 |
| `gse_causal_graph.StructuralObservation` | 单个事件、confidence、uncertainty、一组端口 | 没有结构中心，也没有同帧多实例字段 |
| `CausalStructuralGraph.update(observation, pose, candidates, continuous=...)` | 单事件稳定后建节点；已有候选证据可确认重访 | 时间戳要求严格递增，不能用同一时刻重复调用来塞入多个实例；节点位置写的是机器人 `pose`，不是预测结构中心；稳定计数只按事件类别 |
| `StructuralPort` | 局部 ID、机器人坐标方向、正值宽高、confidence | 当前小头没有宽高，裁剪轴端也不是已确认物理开口 |

因此不能把最大分数 query 直接包装成旧 `StructuralObservation`，也不能把预测中心假装成机器人 `PoseEstimate`：后者会同时污染机器人运动轨迹、边长及配准初值。

## 2. 本轮推荐：先增加无决策候选层

下列窄接口已在独立模块实现，不授权改动冻结训练源：

```python
region_candidates_from_prediction(
    prediction: RegionPrediction,
    axes_current_sensor_m,       # 同一次 forward 的完整轴线，无 GT 筛选
    observation_stamp,           # 调用方提供的真实观测时间与帧名
    robot_from_sensor,           # 显式标定外参；不是 GT 地图位姿
) -> RegionCandidateBatch
```

候选批次应保留：

- 观察时间、传感器／机器人坐标系名称及外参来源标识。
- 完整的观察内 query 编号、预测中心、事件 logits、presence logit、uncertainty 原输出。
- 完整方向 token 编号、机器人坐标的轴端位置及方向、逐 query 的原始 membership logits。
- 模型提供的 `query_supported/member_supported`；它们只表示数值方向是否定义，不能改名为真实可见性或开口验证。
- 明确的候选状态；端口宽高保持“尚未提供”，不制造尺寸和通行结论。

第一版只处理数值与坐标一致性，不执行阈值筛选、top-k、NMS、实例合并、端口确认、节点写入或边提交。完整 32 轴输入产生的 64 个候选全部保留，包括数值不支持的候选；后者保持显式 UNKNOWN，不静默删除或补方向。

中心／轴端位置使用 `R @ point + t`；方向只使用 `R @ direction`。原分数和支持 mask 不因坐标转换改变。这个坐标算子的刚体变换正确性，不等于整个网络获得任意 SO(3) 等变性；现模型声明的是重力对齐共同 yaw 的性质。

观察内 query/token 编号只用于定位当前张量，不是跨帧节点身份。两个候选恰好同中心、同事件时，也不能靠编号先后选择“真正的那个”。

## 3. 禁止的捷径

转换入口不得接收 `loss_only_gt_mask`、`RegionTargets`、teacher direction、构造 node/edge ID、旧采样 `target_node`、评分对齐或训练 Hungarian matches。GT 只存在于训练目标和独立评分路径。

不得为了满足旧 `StructuralPort` 类型而填固定宽高、教师宽高，或直接拼接未经对应验证的旧模型几何属性。尺寸缺失是显式接口缺口，不是允许伪填的理由。

不得从“某个成员分数高”直接推导完整自由空间、可通行连接或全部出口。新候选层表达的是模型的局部结构假设；真实穿越边仍来自机器人执行证据。

不得把当前训练的 `.5` 成员评分阈值当作部署校准，也不得自动沿用旧图 `.8` 事件置信度、`.2` 不确定性、`5` 帧稳定默认值。这些需要后续单独的冻结接口／实验合同；本文件不选择新阈值。

## 4. 后端复用位置与剩余连接

已有模块不重做：

1. `gse_registration_binding.register_candidates()`：当前及历史机器人坐标扫描、部署 `DeploymentPose6D` 与图内候选，生成全部实际配准结果，不自动挑 winner。
2. `gse_registered_node_frame.registered_node_frame()`：将已接受的当前到历史扫描变换，进一步组合到持久节点坐标；历史扫描位姿与节点锚点不是同一个概念。
3. `registered_ports_in_node_frame()`：将已满足旧端口合同的方向转入指定候选节点坐标，不产生对应关系。
4. `gse_port_updates.update_ports()`：消费每个观察端口的完整候选证据；保留歧义为 pending，更新已有端口时保持 attempted/traversed 等执行状态。
5. `CausalStructuralGraph.depart/update()`：显式出发加连续部署位姿形成实际穿越证据。保持已有实现为基线，必要适配放在新版本接口中。

后续最小接线还包括：同帧多实例与跨帧持续跟踪；结构中心和机器人轨迹的独立坐标记录；端口候选证据生成；端口表与图节点生命周期的连接。不能通过修改时间戳、用中心代替机器人位置、只调用第一个通过的配准候选来绕过这些接口。

旧 `gse_trace_commit_replay.replay_trace_commits()` 含按 traversal 计独立支持、事后处理与每段首尾连接逻辑，不是本次在线多实例接线的替代品；不把历史回放自动升级为部署实现。

## 5. 可以提前完成的纯合成验收

这些测试不需要真实数据、新标签或阈值校准：

- 全候选保留：32 轴／64 query、低分及数值不支持项均留在批次中；转换函数没有教师输入接口。
- 同帧双实例：两个中心和两组成员完整保留，不按同类事件或同时间戳合并。
- query/token 置换：输出只按相应编号置换；不影响几何和分数，不产生持久 ID。
- 非零外参：中心带平移，方向不带平移；反射、非有限矩阵、传入时间非法或 stamp／外参坐标系不符明确拒绝。
- UNKNOWN 保真：不支持方向不补单位向量；缺宽高不填常数；转换不输出确认端口或图边。
- 原始输入不可变：转换不修改预测数组、分数、时间戳或支持 mask。

边界说明：`RegionPrediction` 本身不带时间戳或输入身份。转换层只能检查调用方传入的 stamp 合法性、外参 frame 一致性及 axes 的数值支持与预测 mask 一致，不能证明预测和 axes 来自同帧／同次 forward；两个全非退化但错配的数组仍可能具有相同 mask。实际同次 forward 绑定由生产侧保证，本模块不新增身份推断或哈希机制。

等新图 adapter 获得明确提交合同后，可继续用合成序列检查：同类实例切换不串稳定计数；两个配准候选均通过仍保持歧义；首次节点不依赖重访；A→B→C 分别保留两段已执行边；端口更新不重置执行状态；前缀运行和完整运行到同一时刻得到相同图。

## 6. 训练后怎样作最小决策

当前是部分标签容量实验：`label_complete=False`，未匹配 query 没有背景负例。presence 分数不是已验证的检测置信度；事件误差监督的 uncertainty 也不是中心定位、端口对应或回环的校准不确定性。

因此训练后的中心／已知成员改善可以支持“值得继续验证组合接口”，不能直接支持“所有 query 已可作为可靠节点”或完整三分类通过。先完成无决策候选适配及合成接口测试；是否进入真实结构检测／图回放，仍由当前训练证据和后续独立合同决定。不为尽快出图跳过缺失人口、擅改分母或宣称科学 PASS。
