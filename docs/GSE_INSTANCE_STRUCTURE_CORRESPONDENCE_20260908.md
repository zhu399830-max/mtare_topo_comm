# 不能把同一通道当成同一路口

本次运行真实的官方InstanceData.instance_graph和现有primitive_relation_window_targets，而非另写替代公式。命令：`env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 build/gse_supercluster_env_v1/bin/python tools/v3/check_instance_structure_correspondence.py`。会话98974 exit0。纯合成代码记录，无研究数据或训练目标导出。

三个构造通道A、B、C，A末端连接B首端，B末端连接C首端；这是两个结构位置。旧teacher产生4个有向端点关联。将通道身份作为官方对象身份时，A—B和B—C同对象亲和度都是0。反过来，同B的两个表面块亲和度是1，但不表示B两端是同一个结构。

所以端点关联不是整个通道对象的等价关系。若将所有连接都作为聚类正例，传递合并会把多个路口合成一个；若直接用通道ID作实例标签，又会把同一路口的不同通道分开。这排除了直接替换标签的接法，不证明SuperCluster或几何关系学习无效。

相同逐射线来源集合、不同隐藏构造，现有物理关系目标也会不同。这里仅固定来源列表，并非固定完整距离/点云，不能声称已证明两幅真实LiDAR不可区分；它说明来源字段本身不能替代端点支持。已有观测sidecar及未知掩码仍需保留。

## 实施约束与复用

- 分块：组织观测特征，不是语义标签。
- 几何组合：相对位置、法向、高差、射线支持通过已有关系模块输入，不用真实构造ID前向筛选。
- 结构目标：锚点、局部开口及有观测支持的关联，不能将通道实例直接改名为路口。
- 图：跨帧融合与真实穿越连接，不消费超点邻接作为已通行边。
