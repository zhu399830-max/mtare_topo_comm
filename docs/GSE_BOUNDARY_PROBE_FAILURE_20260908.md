# 边界反例未达到全链撤回目标；转向原错误观察

## 本轮实际发生的事

固定合成T路口旋转17度、平移(70.000003,70.000003,0)，五个传感器位置均对应局部(1,1,0.04)。没有搜角度、换阈值或挑选有利场景。新增 `check_gse_joint_precision_boundary.py` 保留失败断言。

第一次执行在mesh生成失败：原采样程序产生不同的末端弧长浮点数，却插值得到完全相同的世界坐标；末端切线为零，归一化产生NaN。这是新的采样实现缺陷，不是模型失败。

修正 `_sample_operand`：仅移除连续、逐坐标完全相等的采样点，保留最后一个即实际端点。不设距离容差、不snap源几何、不删除真实帧。不能直接声称整个历史人口字节不变；无完全重复采样点的输入沿用原数组路径，普通直道逐元素回归通过，三个旋转平移轴线不再产生重复末环或NaN。旧文件与运行不改写，未来正式规格须绑定新源码哈希。

原反例重跑输出：

- 旧锚点0，新锚点0；旧新均三个开口但没有归属列。
- 界面2的9985条进入全部数值未知。
- 离开界面0：8870条全部稳定；界面1：14400条全部未知；界面2：25条全部未知。
- “旧锚点数大于新锚点数”的全链撤回断言失败，退出1。

因此该反例证明真实渲染的边界证据被过滤，**没有证明错误路口标签被撤回**。不修改断言凑PASS，不再搜合成角度或位置来找到一个好看的结果。

## 回归与环境

采样/场/mesh相关17测试在Cano环境通过（0.31s），使用只读追加的已有pytest纯Python包路径，Open3D/NumPy仍来自Cano环境；未安装或更改环境。出现一个dash断言重写警告。此前误用缺Open3D的Torch环境执行该组时4失败/32通过，原因明确为缺依赖，不算算法失败；另一次追加pytest路径定位错误已纠正。

原四个实际CSG联合对照在采样修正后全部通过，开启/关闭精度选项的record仍一致。新真实读取、标签导出和训练均0。

## 下一决定：停止合成场景试错，复验已知真实错误

继续有界原观察纠错验证，而不是扩教师人口。使用已封存S07 rounded_rectangle、序列97000、原五帧3084–3088（1父地图、1物理穿越、1观察），其旧正锚点确实存在且两个方向已被独立源区间检查判未知。准备独立准确数据卡、源码/源文件哈希、一次诊断规格和预检；旧失败run不覆盖、不冒充正式训练资格。

目标输出是旧新锚点/归属差异及每项差异的证据原因。即使锚点被撤回，也只证明该已知缺陷修正，不证明负例人口、完整背景评分或方法增益。若没有撤回，按实际内部/侧面路径解释，不继续无限重跑或换样本。

该有界诊断沿用用户明确的持续纠错授权。它替代此前“必须先在合成场景撤回才能讨论真实复验”的操作顺序；不降低科学验收、不扩大数据范围，不启动第三次全十观察教师批次或训练。本轮只登记决定，尚未创建或执行诊断run。
