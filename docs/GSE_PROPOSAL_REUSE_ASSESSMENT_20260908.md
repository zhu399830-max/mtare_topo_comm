# 三维候选接口复用判断

本次为 Phase 3 / Gate 3 代码与文献只读核查，问题是：能否从实际观测提出三维结构候选，而不借用真实地图身份？新增数据、训练更新和模型推理均为零。背景证据仍为封存的45个合成观察，不代表真实开发集效果。

## 核查结论

| 现有模块 | 实际输入与输出 | 复用边界 |
|---|---|---|
| `teacher/gse_window_opening_proposals_v1.py` | 原始地图网格、指定截面和回波来源编号；输出部分支持的截面参考 | 仅教师诊断。源码明确 `training_eligible=False`；禁止当作部署候选生成器 |
| `representation/gse_point_axis_readout.py` | 点坐标、观测特征、传感器token索引和学习查询；点偏移投票到轴线控制点 | 可复用点级坐标、投票和支持量计算；不是现成结构节点检测器，不能把轴线裁剪端点直接当开口 |
| `representation/gse_region_queries.py` | 全部轴线token的相对位置、方向；输出学习中心与存在性 | 不接收教师中心，但预测质量依赖轴线质量；存在代码不等于候选召回率通过 |
| `topology/gse_region_candidates.py` | 同步预测和轴线，加显式外参 | 无损坐标转换，不筛选、不跟踪、不建图；数值有效不等于可见或可信 |

因此不能声称“已有一个成熟的三维候选器，接上便可成功”。当前缺口是观测支撑到持久结构位置的可靠读出，不是缺少坐标转换代码。

## 成熟方法支持什么

[VoteNet](https://arxiv.org/abs/1904.09664)针对点云表面与对象中心不重合，使用学习投票进行三维检测。它支持考察观测点到中心的投票接口，但没有证明地下路口检测，也不能直接照搬物体框监督。

[Superpoint Graphs](https://arxiv.org/abs/1711.09869)用几何一致的点群及其关系进行点云语义分割。它支持面片关系表示的对照设计，但不提供持久拓扑节点或执行验证的通道边。

推荐保留这两类成熟组件思想，贡献仍由同输入下的结构与图增益证明；不把借用网络组件当创新。

## 下一步与停止条件

先检查已有点轴投票的历史训练与失败证据，判断是否确实比当前自由查询保留了更多位置信息。不得仅因找到VoteNet再训练一轮同类失败接口。该检查只读取代码、运行摘要与既有图，不读取新世界或重新提取特征。

随后才决定是否登记一个观察驱动候选读出的受控对照。新实验必须明确候选召回、直道误检、位置误差及多余预测，所有方法共享候选规则；教师只在损失和独立评分使用。五帧短基线、平行视线或方向对称无法唯一定位时保留未知，不能由平面方向补造三维中心。

旧自由查询配置已用完一次纠错，继续停止扩训、加种子和加数据。现有论文图片和封存运行全部保留。
