# 训练与推理的面片关系输入已统一

## 问题及影响

训练入口 `gse_surface_training_join_v1.py` 过去只提取面片并组批，关系最后三维保持默认 `[0,0,1]`（未知）；推理入口 `gse_surface_prediction_binding_v1.py` 则根据真实五帧射线计算自由/占据/未知比例。训练和运行因此使用了不同的关系信息。当前新方法尚未正式训练，此修正在开训前进行，不代表已有训练成绩作废或新方法已经成功。

## 实现

新增 `representation/gse_surface_observed_inputs_v1.py`，两入口共用同一函数：已对齐XYZ、有效返回掩码、因果帧序号、射线原点→面片→邻居→观测网格→关系特征。默认仍为0.5米面片、10米范围、4096容量和原8邻居，没有新增几何阈值。

训练调用只使用缓存学生点云和原相对运动构建学生网格；用于损失核验的CPU教师网格保持独立，仍由原输入重投影及原来源绑定生成。公共函数不接受构造身份、标签或教师网格。训练header新增构建器版本和学生网格摘要；运行证据直接记录实际送入模型的关系张量，避免另算一份“说明值”。

这不自动证明所有GPU/CPU投影或上游运动对齐完全相同：本次解决的是**相同已对齐观测进入关系构建时的处理不一致**。CUDA数值一致性仍需可用设备验证。

## 验证结果

- 纯合成双端射线反例：旧组批对已观察自由间隙输出未知；新共同构建实际输出 `[1,0,0]`。重复构建的全部batch字段逐元素相同。
- 无效返回不产生自由/占据空间；空面片保持未知。
- 实际训练join的全部面片batch字段与共同构建结果一致；教师context保持独立。
- 实际推理模型、源摘要、因果帧、坐标变换、同观察重复、障碍证据和图接线既有测试通过。
- 七个测试文件合计 **95 passed、1 skipped，2.78秒**。跳过的是CUDA缓存/CPU教师网格测试，原因是当前CUDA不可用，不能记作通过。

初次重构遗漏了证据日志中旧局部变量，测试捕获NameError；已改为从模型实际输入张量记录，随后全组通过。未执行真实数据导出、模型训练或标签重跑，未修改任何历史结果和论文图片。
