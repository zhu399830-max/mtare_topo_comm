# 路口参考界面的射线证据接线

2026-09-07。本步是软件和合成验证，不是新模型结果。

## 完成了什么

原Open3D求交后端现在可以保留同一条激光穿过的多个构造界面、三维交点和先后顺序。每个原始网格分别求交，避免重合的不同来源被丢掉。只有首次返回前、当前10米球域内的交点参与顺序记录；界面重合不强行排序，不跨歧义连接。

五帧适配器先检查原始观测与构造来源一致性，再保留原始帧行号、射线槽、端点归属及返回来源集合。同一通道的两个端点独立保留，多来源返回不强行变成唯一来源。所有构造身份仍只在教师诊断内。

## 实际验证

- 主环境15项相关测试通过，1项Open3D测试因该环境未装Open3D跳过。
- 在已有Open3D环境实际执行`tests/v3/unit/check_gse_interface_caster_backend_v1.py`：顺序、来源排列、遮挡、上下层、重合、球域、重复归属与帧来源检查通过，耗时约0.91秒。不是以跳过代替后端验证。
- 新真实地图/观测读取0，新语义标签0，训练更新0；原封存结果不变。

## 结论边界和下一步

这比“几条分支各出现过回波”保留更多空间证据，但参考端面可能是内部构造界面，不等于可见开口；一条自由射线也不等于地面存在、车身能通过或完整路口可见。不能把此检查升级为必要/充分语义门，更不能要求每对分支都被同一条直线穿过：弯曲可通通道未必满足。

下一步在既定真实观察范围绑定正式诊断，检查这些界面证据和实际表面边界是否对应；若不能区分相邻或分层结构，不允许据此直接生成路口标签。不是继续增加旧模型训练次数。
