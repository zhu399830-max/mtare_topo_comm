# 双通路数据接线：本轮交付

2026-09-06。研究问题不变：同一观测、位姿和后端，几何组合是否改善结构图。此次仅源码、配置核查和合成测试，**没有新的真实数据读取、人工标签、权重加载或训练**。48片段/3024观察尚不是实际清单。

## 接好了什么

1. **旧数据索引→连续片段索引**：[source index](../src/mtare_topo/data/gse_review_source_index_v1.py)核对三变体、原序列身份、五帧来源和有向穿越边界，枚举所有合法21步区间。短穿越报告不足，不补帧、不命名结构类别。
2. **选定扫描→匿名复核点云**：[exporter](../src/mtare_topo/data/gse_review_export_v1.py)使用与学生相同的`register_causal_lidar_points`，保留全部有效回波和原三维坐标。21步逐一绑定来源；重复出现的同一原帧必须字节一致。抽样类别、构造身份只留在私有证据，不进入盲看包。
3. **旧编码器→新双通路模型**：[adapter](../src/mtare_topo/representation/gse_dual_path_encoder_adapter_v1.py)冻结旧编码器，按真实扫描位置找到所属特征，不用构造身份分组。同一压缩特征下的上下层回波仍保留不同XYZ。旧编码器不接收梯度，新模块正常接收梯度。
4. **人工复核参考的显示前检查**：浏览器原来可能先显示错误参考、到Python导入才报错。现在先核实际盲看文件字节哈希和参考结构，再允许显示；重复JSON字段与超大文件也提前拒绝。见[协议修正](GSE_REVIEW_IMPORT_BOUNDARY_V1.md)。原始盲看判断仍不可回填。

## 为什么不存全部逐点特征

3024观察×57600点×128维×4字节，仅重复特征就约89.18GB，超过30GiB证据预算。因此缓存900个压缩传感器特征，逐点展开只在当前批次进行。当前compact字段连同全部XYZ、mask和索引，float32下每观察1,670,400字节，3024观察约4.70GiB。

这是软件尺寸计算，**不是实际磁盘占用或训练显存实测**；还要计入复核材料、扫描、标签、权重和其他证据。资源预检仍需执行。没有为减少占用删除点、改变模型信息或修改历史资产。
