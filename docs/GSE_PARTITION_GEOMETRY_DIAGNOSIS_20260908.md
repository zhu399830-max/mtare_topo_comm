# 超点能压缩分块，但不能直接替代小平面

## 结论

同45例已封存输出的只读检查完成。超点原点映射完整，但将每个超点仅概括成“中心＋法向”会丢失块内形状。因此，不把R2直接接到原来的面片属性读出上，也不据此宣布R2无效。应保留块内点云编码，和当前坐标中的块间布局；这与已固定SPG源码的实际接口一致。

本次未改分块参数、标签、样本、模型或评分标准，未新增训练。检查脚本为`tools/v3/inspect_paired_partition_geometry.py`，读取前验证上一轮seal与每个输出SHA；输出完整45例JSON到标准输出，不修改封存运行。

## 什么证据支持这个判断

计算每个实际回波到其分块中心/法向定义平面的距离，再计算平方均值的平方根。只对有明确法向的点计算，同时报告未纳入的点数。这是**平面概括损失**，不是对真值地图的几何预测误差，也不是新的路线胜出指标。

| 同一批观测 | 固定体素面片 | 超点 |
|---|---:|---:|
| 平面概括残差RMS | 0.00987米 | 0.30597米 |
| 有明确法向的点 | 2,431,891 | 2,435,326 |
| 法向未知的点 | 3,435 | 0 |
| 最大分块观测包围盒对角线 | 0.854米 | 19.781米 |

分块规模相差很大，所以不能仅凭这个表判定超点算法差。大块沿直墙延伸十几米也可以合理；“法向有效”只代表PCA数值可辨认，不保证一整块是平面。

三个具体例子：

- **圆角矩形直道 view0**：超点的平面残差约0.00886米，与体素面片0.00815米接近。最大的块沿一侧墙延伸约16.82米，说明大块并非天然有问题。
- **圆形T路口 view2**：超点整体平面残差约0.359米，体素面片约0.00436米；单平面不再能概括超点内部形状。
- **圆角矩形尽头 view2**：第13个超点含41,579/55,607个点，Y范围约−2到+2米，跨两侧墙；其中心距最近实际回波约1.999米。该块自身平面残差约0.448米。因此块中心不能冒充观测表面点，更不能自动成为路口节点。

## 成熟实现实际如何做

已检查本地固定SPG提交`0209777339327c9b327b6947af6c89b20bb45981`的代码：

- `learning/spg.py::load_superpoint`读取每个超点的点云，形成局部坐标，并另存尺度；不是只输出中心和法向。
- `learning/pointnet.py::PointNet.forward`对块内点逐点编码，再最大池化得到块特征，随后结合全局属性。

这解释了为什么不能将官方分块算法和我们的“每块一个平面”接口直接拼接，并称为完整SPG基线。历史权重和旧损失都不因此获得重新训练许可。

## 接下来只做必要的软件接线

建立两种分块共用的块内点输入：保留原始当前坐标、相对块中心坐标、真实尺度、五帧来源及点到块映射；不用构造身份筛选，不因小块丢弃观测。采用有界的逐点编码/分块聚合接口，避免全点两两注意力和一次展开全人口高维特征。

首先检查点顺序与分块编号置换、空/退化输入以及全点与分批聚合一致性，不训练。然后再登记共同读出和公平比较，避免一边给完整点云、一边只给均值却归因于几何关系。

这项工作只解决“几何表示如何进入模型”的接口。结构监督不足、旧检测头失败和独立建图收益未证实的问题仍然存在，Phase3不因此通过。
